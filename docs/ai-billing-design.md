# AI 调用账单设计

## 目标与计费口径

管理员在“AI 账单”页面设置实时固定单价，也可以选择时间段、为该账期分别填写三类接口的单价，预览后生成或重新生成账单。按账期、App ID、账户及接口查看汇总和逐笔明细，并导出 PDF 对账单。

计费对象仅为已鉴权的对外 OpenAPI 请求。每次 Coze 成功生成且配置了正数单价，记一笔应收；401、缺权限、参数错误、账户无效、生成失败不收费；mock 调用免费。未配置单价时记录为“待定价”，金额为零，不能事后自动改写成应收。前端将“分”换算为“元”展示，不采用浮点金额持久化。

## 数据流

1. OpenAPI 原有鉴权、scope、限流和控制器参数检查通过后，创建 `BillingEntry(pending)`。此前失败的请求不进入账单。
2. 调用 AI 适配器。失败则将记录改为 `failed`，金额零。进程意外退出留下 `pending`，供人工核查，不自动收费。
3. 成功后根据返回的 `provider` 和当前 `BillingRate` 生成 `charged`、`free` 或 `unpriced` 状态；将当次单价和金额写入逐笔记录，再向客户端返回结果。账单写入失败时接口不会返回“成功”，防止成功结果缺少对账记录。
4. 管理员使用只读账单 API 汇总与查看明细；PDF 由浏览器打印窗口生成，适合中文字体。账单记录独立于 90 天 TTL 的调用审计日志，不存请求内容或 AI 回答。

## 历史账期与重算

旧调用日志没有逐笔提供方字段；运营方已确认旧洞见调用均由 Coze 生成。因此旧版 `/card-insight`、`/daily-insight`、`/tutor-chat` 及其 `/openapi/v1` 路径中，只有 HTTP 200 且能归属 App 和账户的记录可以生成历史账单；每笔标记来源 `historical-inferred`，以区别具有提供方快照的实时记录。日志没有账户 ID 时尝试从 App 绑定关系补全；仍无法归属则整个生成操作被拒绝，不能静默漏计。

账期使用 `[from,to)` 时间范围，UI 按北京时间自然日选择，结束日期包含在内。每个账期有独立的三类接口价格与不可变的逐笔版本快照，版本记录生成时间和管理员 ID。管理员改价重算时新增版本，旧版本可查看与导出；原始实时 `BillingEntry` 不被覆盖。不同账期不能交叠，避免同一调用被重复出账。预览返回来源和价格指纹，生成时必须重新核对；金额以整数“分”保存。旧日志 90 天过期后，已经形成的逐笔账期快照仍可重算；尚未生成而且已经过期的日志只能通过备份另行恢复。

## 对账边界

管理员可以分页浏览已生成账单并打开查看，也可确认删除整个账期。删除永久清除该账期全部版本数据和逐笔快照，仅保留账期标识及删除人、时间、版本号审计；已删除账期不再参与日期重叠检查，不能继续查看或导出。调用日志与实时流水不变。删除与生成共享互斥锁，并检查管理员看到的版本号，防止误删刚更新的账单；删除接口可安全重试。重新选择相同或扩展日期出账时只依据仍存在的调用来源，不复用已删除快照。原始调用日志 90 天后自动过期，删除前界面明确提示过期数据可能无法重建。已下载 PDF 无法自动撤销。

每笔账单有唯一记录 ID，成功响应在 `X-Billing-Entry-Id` 返回它。列表展示时间、App ID、账户 ID、产品、提供方、状态、当时单价和金额。账期按北京时间自然月，后端使用 `[from, to)` 范围。导出上限 5000 条，超过时须缩小筛选范围。

旧调用日志本身不是成交账单：它没有当时的成交单价快照，且会在 90 天后删除。历史账单由管理员明确选择价格并确认生成；账单显示运营方确认的旧 Coze 归属和对应版本。期间实际用量或 Coze token 成本仍不在本系统中复原。

## 后续增强

当前账单是对外固定单价的**应收对账**，不是 Coze 的实际 token 成本报表；Coze 工作流响应目前没有在适配器中提供用量明细。后续可增加 Coze 用量采集、退款/冲正记录、发票与付款状态、账期结算锁定、客户自助下载，以及超过 5000 行的异步批量导出。
