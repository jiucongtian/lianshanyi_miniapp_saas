# AI 调用账单设计

## 目标与计费口径

管理员在“AI 账单”页面设置智慧洞见、每日愈见、助学童子各自的人民币固定单价，按账期、App ID、账户及接口查看汇总和逐笔明细，并导出 PDF 对账单。

计费对象仅为已鉴权的对外 OpenAPI 请求。每次 Coze 成功生成且配置了正数单价，记一笔应收；401、缺权限、参数错误、账户无效、生成失败不收费；mock 调用免费。未配置单价时记录为“待定价”，金额为零，不能事后自动改写成应收。前端将“分”换算为“元”展示，不采用浮点金额持久化。

## 数据流

1. OpenAPI 原有鉴权、scope、限流和控制器参数检查通过后，创建 `BillingEntry(pending)`。此前失败的请求不进入账单。
2. 调用 AI 适配器。失败则将记录改为 `failed`，金额零。进程意外退出留下 `pending`，供人工核查，不自动收费。
3. 成功后根据返回的 `provider` 和当前 `BillingRate` 生成 `charged`、`free` 或 `unpriced` 状态；将当次单价和金额写入逐笔记录，再向客户端返回结果。账单写入失败时接口不会返回“成功”，防止成功结果缺少对账记录。
4. 管理员使用只读账单 API 汇总与查看明细；PDF 由浏览器打印窗口生成，适合中文字体。账单记录独立于 90 天 TTL 的调用审计日志，不存请求内容或 AI 回答。

## 对账边界

每笔账单有唯一记录 ID，成功响应在 `X-Billing-Entry-Id` 返回它。列表展示时间、App ID、账户 ID、产品、提供方、状态、当时单价和金额。账期按北京时间自然月，后端使用 `[from, to)` 范围。导出上限 5000 条，超过时须缩小筛选范围。

已有的调用审计日志不能作为正式历史账单：它没有 AI 提供方与成交单价快照，且会在 90 天后删除。若未来要补收历史费用，需要另行取得业务确认、约定历史价格与核对依据后执行一次性迁移。

## 后续增强

当前账单是对外固定单价的**应收对账**，不是 Coze 的实际 token 成本报表；Coze 工作流响应目前没有在适配器中提供用量明细。后续可增加 Coze 用量采集、退款/冲正记录、发票与付款状态、账期结算锁定、客户自助下载，以及超过 5000 行的异步批量导出。
